# AIR Sanitized AI Incident Diagnostics & Diagnostic Analyzer

## Overview

AIR's diagnostic layer allows optional AI models or offline deterministic analyzers to inspect incidents, generate root-cause hypotheses, and recommend operator actions without granting any operational authority.

### Invariant
**AI DIAGNOSTICS ARE STRICTLY READ-ONLY AND ADVISORY.**
The diagnostic interface contains **zero action handles**, **zero execution tools**, and **zero access to SecurityAdapters or RecoveryAdapters**.

---

## 1. Sanitized DiagnosticContext

`buildDiagnosticContext()` extracts a frozen, sanitized data representation from security and operational incidents:

```json
{
  "schemaVersion": "air.diagnostic.context@1",
  "incidentId": "inc_123",
  "status": "open",
  "severity": "error",
  "primaryComponent": "security",
  "failureCode": "password_spray_pattern",
  "summary": "Password spray detected on source 198.51.100.42",
  "timeline": [
    "19:20:01 [WARNING] auth: auth.login.failed",
    "19:20:03 [WARNING] auth: auth.login.failed"
  ],
  "eventAggregation": {
    "totalEventCount": 42,
    "distinctSourcesCount": 1,
    "distinctIdentitiesCount": 11,
    "distinctErrorCodes": ["AUTH_FAILED"],
    "sampleEventIds": ["evt_1", "evt_2"]
  },
  "evidenceEventIds": ["evt_1", "evt_2", "evt_3"],
  "untrustedEventData": [
    { "eventId": "evt_1", "content": "user_input_content" }
  ]
}
```

### Safety & Privacy Guarantees
1. **Secret Redaction:** `globalRedactor` removes passwords, bearer tokens, connection strings, and registered secrets.
2. **PII Minimization:** Raw email addresses and personal data are stripped; actor IDs are used.
3. **Event Flood Aggregation:** Repetitive events are compressed into statistical summaries rather than generating massive prompts.
4. **Prompt Injection Barrier:** Untrusted user input (usernames, error strings, query params) is quarantined inside `untrustedEventData` and never interpolated into system instructions.

---

## 2. Structural Fact vs Inference vs Recommendation Separation

Every `DiagnosticReport` generated by `DiagnosticAnalyzer` enforces a strict schema separation:

1. **Facts (`facts`):** Verified historical facts that MUST cite valid `evidenceIds` present in the `DiagnosticContext`.
2. **Inferences (`inferences`):** Hypotheses generated by the analyzer with explicit confidence levels (`high evidence`, `moderate evidence`, `limited evidence`).
3. **Recommendations (`recommendations`):** Human-readable plain text prose recommendations for operators. Executable tool objects or parameter schemas are strictly rejected.

---

## 3. Deterministic Diagnostic Analyzer

AIR includes an offline `DeterministicDiagnosticAnalyzer` requiring zero external API keys or cloud dependencies:
```bash
# Operator inspection of diagnostic context
npm run air -- security diagnostic-context <incident-id>

# Run deterministic diagnostic report
npm run air -- security diagnose <incident-id>
```

---

## 4. Diagnostic Report Validation

`DiagnosticReportValidator` verifies that:
- Every fact statement cites valid, non-fabricated evidence event IDs.
- Recommendations are text strings only.
- The report contains no executable functions or adapter references.
